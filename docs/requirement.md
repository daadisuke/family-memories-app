# 家族思い出アプリ 要件定義書

## 1. プロジェクト概要

### 1.1 目的
家族の写真を簡単に整理・共有・検索できるWebアプリケーションを構築する。AIを活用して写真を自動的にタグ付けし、家族間でスムーズに思い出を共有できるようにする。

### 1.2 ユーザーストーリー
- これまでの写真を整理したい
- どこからでも見たい
- まとめてアップしたい
- 写真を条件で検索したい
- ゆくゆくはAIを使ってソートしたい

## 2. 機能要件

### 2.1 認証機能
- ユーザー登録・ログイン機能
- NextAuth.js による認証
- セッション管理

### 2.2 写真アップロード機能
- 複数写真の一括アップロード対応
- Supabase Storage へのファイル保存
- アップロード進捗表示
- サポートファイル形式: JPEG, PNG, HEIC など

### 2.3 写真管理機能
- アップロード済み写真のギャラリー表示
- 写真メタデータの管理（パス、アップロード日時、タグ等）
- PostgreSQL でのメタデータ保存
- 署名付きURLによる画像表示

### 2.4 写真検索機能
- タグによる検索
- 日付による検索
- 人物による検索（将来的に）
- フリーワード検索

### 2.5 家族共有機能
- 家族アカウントの階層構造
  - 夫
  - アンディ（にくなる）
  - 妻
  - テディ
  - 赤ちゃん
- 家族間での写真共有
- アクセス権限管理

### 2.6 AIタグ付け機能（将来実装）
- FastAPI + Claude Code MCP を使用したAI処理
- 自動的な画像認識とタグ付け
- 人物認識
- シーン認識
- オブジェクト認識

## 4. システムアーキテクチャ

### 4.1 データフロー（写真アップロード）

```
ユーザー
  ↓ 写真選択してアップロード
Next.js (ブラウザ)
  ↓ 認証確認
NextAuth
  ↓ OK (ユーザーID取得)
Next.js
  ↓ ファイルアップロード
Supabase Storage
  ↓ アップロード成功 + ファイルパス
Next.js
  ↓ INSERT (photo metadata: path, user_id, timestamp, tags=null)
Supabase PostgreSQL
  ↓ INSERT成功
Next.js
  ↓ ギャラリー更新
ユーザー（写真表示成功）
```

**注**: 写真はアップされた時点ではタグなし状態。将来的にファイルパスを使ってAIタグ付け要求を実行。

### 4.2 主要コンポーネント連携

- **ログイン**: NextAuth.js ↔ PostgreSQL
- **アップロード**: Next.js → Supabase Storage → PostgreSQL（メタデータ記録）
- **API呼び出し**: Next.js → FastAPI（レスポンス）
- **CI/CD**: GitHub → Vercel (フロント), Render/Railway (API)

## 6. 非機能要件

### 6.1 パフォーマンス
- ページ読み込み時間: 3秒以内
- 画像アップロード: 進捗バー表示
- 画像表示: 遅延読み込み（Lazy Loading）対応

### 6.2 セキュリティ
- 認証必須（未ログイン時はアクセス不可）
- 家族グループ外の写真は閲覧不可
- 署名付きURLによる画像アクセス制御
- HTTPS通信

### 6.3 可用性
- Vercel/Supabaseによる高可用性
- 自動バックアップ（Supabase機能）

### 6.4 スケーラビリティ
- ストレージ容量は必要に応じて拡張可能
- サーバーレスアーキテクチャによる自動スケーリング

## 9. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| ストレージ容量超過 | 高 | Supabase容量監視、必要に応じてプラン変更 |
| AI処理コスト増大 | 中 | バッチ処理、必要な写真のみ処理 |
| 認証関連のセキュリティ問題 | 高 | NextAuth/Supabase Authの標準機能を使用 |
| 画像表示速度の低下 | 中 | CDN利用、画像最適化、遅延読み込み |
